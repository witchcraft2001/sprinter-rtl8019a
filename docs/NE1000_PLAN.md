# План: поддержка ISA-8 NE1000 наряду с NE2000 / RTL8019AS

Статус: выполнен, редакция 6 от 2026-09-22. После проверки рабочего
`NE2000.COM` v11.4.3 и исходников Crynwr принято дополнительное решение:
remote write выполняется прямой последовательностью без фиктивного чтения.
Ветка `ne1000-support`, база -- пакет 0.3.28, целевая версия -- 0.4.0.
Документ только для разработки: в `DIST_DOC_FILES` не добавлять (как
`MAME_NETWORK.md`).

## 0. Коротко

- Раскладка NE1000 -- это текущая раскладка, сдвинутая на `-0x20` страниц:
  пакетная RAM с `0x20`, а не с `0x40`. Кольцо RX в обоих случаях 26 страниц,
  поэтому TCP-окно, MSS, `RX_DRAIN_BUDGET` и стек не меняются.
- Кроме адресов, настоящий DP8390 оставляет STA установленным после STP, а
  `ISR.RST` нельзя сбросить записью (2.5); обе особенности учтены в драйвере.
- Все три пути записи (`DMA_WRITE`, `DMA_WRITE_SG` и G6 `NICREG`) используют
  прямую последовательность Crynwr: параметры, команда, data port (2.4).
- Тип карты -- параметр времени выполнения. Один набор `.EXE` и одна
  `UNETRTL.DLL` работают с обеими картами, пересборка не нужна.
- Тип определяется **только** в `NETCFG -i` (и в `IFUP`, если переменной нет)
  либо задаётся ключом `RTL_TYPE=` в `NET.CFG`; публикуется как
  `NET_RTL_TYPE=NE1000|NE2000`. Остальные утилиты и DLL читают переменную в
  `RTL.INIT_BASE`. Одно исключение -- `NICINFO`: сверочная проба только на
  печать, без публикации.
- Автоопределение распознаёт две стандартные раскладки: ID `Pp` -> NE2000 без
  проб; иначе -- проба RAM по `0x4000` и `0x2000` через remote DMA (приём
  FreeBSD `if_ed`). Предусмотрены неоднозначный результат, ошибка DMA,
  неисправный контроллер и ручной выбор; публикуется только однозначный
  результат, и публикация проверяется чтением назад (4.3, 4.5).
- `RTL.INIT_BASE` остаётся чистой функцией SDK: возвращает различимый статус,
  не печатает и не завершает процесс (4.3).
- Место: в `UNETRTL.DLL` свободно 20 байт, в `TELNET.EXE` -- 26, а работа
  стоит +70..+110. Источник байт -- мёртвый код: 81 байт в DLL и 60 в TELNET
  измерены, ещё ~340 в TELNET -- кандидаты (4.7). Узкое место -- DLL.
- Попутно исправляется реальная ошибка: `NETCFG` определяет "удвоенный" PROM
  по одной паре байт и ломает MAC с OUI `00:00:xx` (Novell `00:00:1B`). Новый
  разбор PROM выбирает единственное прочтение, согласное с документированным
  форматом, а иначе честно говорит "неоднозначно" (4.9).

## 1. Цель и рамки

Цель: карты ISA-8 класса NE1000 (DP8390/DP83901 + 8 КБ SRAM по адресу
`0x2000`) работают со всем пакетом -- диагностика, `PING`...`FTP`, `TELNET`,
`UNETRTL.DLL` -- наравне с RTL8019AS и NE2000-клонами.

Входит в работу:

- раскладка пакетной RAM и подготовка remote write как параметры времени
  выполнения в драйвере; совместимость проверок `CR`/`ISR` с DP8390;
- ключ `RTL_TYPE` в `NET.CFG`, переменная `NET_RTL_TYPE`, автоопределение в
  `NETCFG`/`IFUP`;
- диагностические утилиты без зашитых адресов `0x40xx`;
- модель NE1000 в host-харнессе, прогон в MAME (`-isa1 ne1000`), затем на
  реальной карте;
- документация, спецификация (включая контракт SDK для `INIT_BASE`),
  `CLAUDE.md`/`AGENTS.md`.

Не входит:

- 16-битный режим, IRQ, другие семейства (3C503, WD80x3);
- автопоиск NE1000 по базовым адресам (решение Q2);
- изменение замороженного ABI `unet.inc`.

## 2. Чем NE1000 отличается

### 2.1 Сводка

| Свойство | RTL8019AS / NE2000 в 8-бит слоте (сейчас) | NE1000 |
|---|---|---|
| Регистры `BASE+0x00..0x0F`, data `+0x10`, reset `+0x1F` | да | то же самое |
| `DCR` | `0x48` (loopback `0x40`) | то же самое |
| Пакетная RAM | `0x4000..0x5FFF` (используем 8 КБ) | `0x2000..0x3FFF` (8 КБ) |
| `TPSR` | `0x40` | `0x20` |
| `PSTART` = `BNRY` | `0x46` | `0x26` |
| `CURR` | `0x47` | `0x27` |
| `PSTOP` | `0x60` | `0x40` |
| Кольцо RX | 26 страниц | 26 страниц |
| PROM при байтовом чтении | удвоенный (NE2000) либо прямой `BB` (RTL/UMC в 8-бит слоте) | прямой, 16 байт, `57 57` в `0E/0F` |
| ID `0x0A/0x0B` стр. 0 | `50 70` у Realtek | нет (DP8390) |
| Страница 3 | только Realtek | нет -- выбирать нельзя |
| Remote write | прямая последовательность | прямая последовательность (2.4) |
| `CR` после записи STP | читается как записан | STA может остаться установленным (2.5) |
| `ISR.RST` | -- | только статус, записью не сбрасывается (2.5) |
| Типичный OUI | разный | Novell `00:00:1B` |

Все значения раскладки = `база + {0, 6, 7, 0x20}`.

### 2.2 Источники (сверить при реализации, код не импортировать)

- National DP8390D datasheet: раздел 9, стр. 13-14 -- remote write; раздел
  10.3, стр. 19-20 -- `CR` (STP/STA) и `ISR.RST`.
- Realtek RTL8019AS datasheet (8-битный режим, `PSTOP <= 0x60`, PROM `0E/0F`
  = `57`/`42`).
- Linux `drivers/net/ethernet/8390/ne.c`: `NE1SM_START_PG=0x20`,
  `NE1SM_STOP_PG=0x40`, `NESM_START_PG=0x40`; `NE_RW_BUGFIX`.
- FreeBSD `sys/dev/ed/if_ed_novell.c` (`ed_probe_Novell_generic`): тип
  определяется пробой RAM; формат PROM выбирается по типу карты.
- MAME в локальном дереве:
  - `bus/isa/ne1000.cpp`: I/O жёстко `0x300`, RAM 8 КБ, адрес маскируется до
    14 бит, PROM 16 байт (MAC + `0x57`), за его пределами `0xFF`, MAC
    `00:00:1B:xx:xx:xx`, чип `DP8390D`; есть в `pc_isa8_cards`, т.е.
    `-isa1 ne1000` доступен на Sprinter уже сейчас;
  - `bus/isa/rtl8019as.cpp`: PROM 32 байта, заполнитель `0x57`, формат --
    **опция конфигурации** ("RTL8019AS PROM layout", бит `0x40`), по
    умолчанию **прямой**. (В редакции 3 этот стенд ошибочно назван
    "удвоенным"; исправлено, см. 4.9.)

### 2.3 Почему PROM-сигнатура не годится для выбора раскладки RAM

`docs/NICEEP.md` фиксирует измерение: UM9003AF в слоте ISA-8 показывает в PROM
`42 42` ('BB' = "NE1000/8-бит"), но работает с раскладкой `0x40`. RTL8019AS в
8-бит слоте по даташиту тоже отдаёт `42`. `BB` означает "шина 8 бит", а не
"RAM по адресу `0x2000`". Раскладку выбирает только проба RAM или явный
`RTL_TYPE`.

### 2.4 Remote write

Проверенный на реальном оборудовании `NE2000.COM` v11.4.3 и исходники
Crynwr NE1000/NE2000 программируют настоящие `RBCR/RSAR`, выдают remote
write и сразу передают данные через data port. Фиктивного remote read нет.
Linux содержит опциональный, по умолчанию выключенный `NE_RW_BUGFIX`; его
комментарий прямо предупреждает, что метод National не работает, а вариант
Crynwr также работает не всегда. Это недостаточная основа для обязательной
последовательности в нашем драйвере.

На UM9003AF дополнительно измерено, что предвыбранный байт может остаться в
FIFO и сдвинуть следующую передачу. Поэтому драйвер повторяет прямую
последовательность Crynwr и не требует изменения общей модели DP8390 в MAME.

### 2.5 `CR` и `ISR` на DP8390

- Если контроллер уже был запущен, после записи STP **оба** бита STP и STA
  могут читаться установленными. Чтение `0x23` после записи `0x21` -- норма,
  а не неисправность; двойное чтение этого не меняет. Программный сброс
  (`CR=0x21`) оставшийся STA не снимает -- только аппаратный. Поэтому случай
  "вторая утилита в той же сессии" на NE1000 -- основной, а не краевой:
  `RTL_RESET` в AUTO даёт для не-Realtek чипа именно программный сброс.
- `ISR.RST` -- бит состояния: устанавливается при входе в reset-состояние,
  сбрасывается командой START, записью единицы не очищается. После
  `ISR=0xFF` в остановленном чипе законно читается `0x80`.

Это касается не только нового детектора, но и существующего кода -- см. 3.17.

## 3. Что в коде мешает сейчас

1. **Раскладка -- константы времени сборки.**
   [rtl8019.inc](../src/include/rtl8019.inc) строки 245-264. Использований: 31
   в [rtl8019.asm](../src/lib/rtl8019.asm), 19 в
   [nicreg.asm](../src/apps/nicreg.asm) (включая `G6_ADDR EQU 0x4000`, таблицы
   ожидаемых значений и `ASSERT`), таблица `TEST_CASES` в
   [nicram.asm](../src/apps/nicram.asm), текст `MSG_L1` в
   [niclb.asm](../src/apps/niclb.asm).
2. **Тип карты не определяется.** `RTL_CHIP_KIND` различает только
   `REALTEK`/`CLONE`, и в DLL не заполняется вовсе.
3. **Готовый образец цепочки уже есть:** `NET.CFG RTL_HW/RTL_RESET` ->
   `NETCFG -i` -> `NET_RTL_HW`/`NET_RTL_RESET` -> `RTL.INIT_BASE`.
4. **Авто-скан баз требует `Pp`.** NE1000 им не найдётся; `NICINFO` файл
   `NET.CFG` не читает. По той же причине шаг probe мастера `NETCFG -w`,
   который идёт **до** ввода `RTL_HW`, для новой NE1000 не сработает.
5. **Ошибка в `NETCFG.FILL_MAC_FROM_PROM`:** "удвоенность" PROM решается по
   одной паре `PROM[0]==PROM[1]`. `NICINFO.DETECT_LAYOUT` проверяет три пары
   -- два разных алгоритма для одного PROM. Кроме нулевого, MAC из PROM никак
   не проверяется.
6. **`DMA_READ`/`DMA_WRITE` при таймауте RDC возвращают `CF=1`, не отменяя
   DMA и ничего не меняя в регистрах.** Зато каждая из них **начинается** с
   отмены (`CR_PAGE0_START` несёт RD2). Это полезное свойство: состояние
   отказа остаётся нетронутым для того, кто захочет его снять (4.4).
7. **`FILL_MAC_FROM_PROM` запускает remote DMA, не переведя приёмник в
   monitor mode.**
8. **`NICRAM`: нулевой адрес -- признак конца таблицы** (`JP Z,ALL_OK`).
9. **Три пути remote write, а не два.** `RTL.DMA_WRITE`
   ([rtl8019.asm](../src/lib/rtl8019.asm):1124), `RTL.DMA_WRITE_SG` (:1243) и
   `NICREG` G6 ([nicreg.asm](../src/apps/nicreg.asm):1801). Других мест в
   дереве нет (`grep CR_DMA_WRITE`).
10. **`NETCFG` не проверяет результат `SETENV`.** `SETENV_STR`,
    `SETENV_LITERAL`, `DELETE_VAR` делают `RST DSS` и `RET`. В харнессе отказ
    уже моделируется (`envFailAt`).
11. **Статический `IFUP` объявляет успех без обмена пакетами:**
    `INIT_NORMAL` -> `ISA_CLOSE` -> `PUBLISH_NET_MARKER` -> `EXIT_OK`.
12. **Модель чипа:** CRDA двигается при обращении к data port, как в штатной
    модели MAME; время в модели -- `currentMs`, которое харнесс подаёт из
    `logicalMs`, тогда как счётчик
    тактов Z80 (`cycles`) в харнессе есть, но в модель не передаётся; `CR`
    читается ровно как записан; `ISR.RST` сбрасывается записью; RAM жёстко
    `0x4000..0x7FFF`; варианты только `RTL8019AS`/`UM9003`.
13. **Бюджет образов.** `UNETRTL.DLL`: 20 байт до `ASSERT`. `TELNET.EXE`:
    26 байт.
14. **Мёртвый код.** Измерено: `SNAPSHOT_REGS` в DLL -- 81 байт, других
    кандидатов в DLL сканирование меток не нашло. В TELNET измерено:
    `PROBE_PRESENT` (9), `PROBE_ID` + `ID0/1_RAW` (42), `READ_PROM` (9) -- 60
    байт. Кандидаты в TELNET (**не проверены на fall-through и макросы**):
    `NETENV.GET_STR` (32), `GET_U16` (48), `CMDL.HAS_FLAG` + `GET_FLAG_VALUE`
    (38), `UTIL.PRINT_HEX_HL` + `PRINT_MAC` (39), `ZPRINT_*_DIAG` в zmodem
    (183) -- ~340 байт.
15. **`LASTERR` в DLL работает до успешного `NETINIT` и без cold-блоба.**
16. **`NETENV._MISSING` -- внутренняя точка перехода**, а не процедура.
17. **`SELECT_PAGE` сверяет `CR` по маске `CR_VERIFY_MASK = 0xC3`, то есть
    вместе с STA.** На DP8390, который уже запускался, любая запись
    STOP-значения (`CR_PAGE0_STOP`, `CR_PAGE1_STOP`) прочитается с STA=1,
    не пройдёт сверку, сожжёт все четыре попытки и вернёт `CF=1`.
    `INIT_NORMAL` этот `CF` игнорирует (потеря -- только время), но `NICREG`
    ([nicreg.asm](../src/apps/nicreg.asm):1488) пользуется той же маской и
    покажет ложные потери записи. Кроме того, комментарий к `SELECT_PAGE`
    описывает совпадение диапазона кольца `0x46..0x5F` со страницей 1 под
    маской; у NE1000 кольцо `0x26..0x3F` совпадает уже со страницей 0.
    **Вторая, независимая сверка `CR` -- `G3_TABLE` в `NICREG`**
    ([nicreg.asm](../src/apps/nicreg.asm):2353):
    `DB 0x00, CR_PAGE0_STOP, 0xFF, "CR   "` -- своя маска `0xFF`, общая
    `CR_VERIFY_MASK` её не затрагивает. Законное `0x23` G3 засчитает как
    ошибку чтения. Других сверок `CR` в дереве нет: остальные `CP 0x21` --
    это байт статуса RX в `NICLB` и ASCII в разборе строк.
18. **Измерение на UM9003AF о предвыборке и FIFO** (комментарий к
    `G6_DMA_START`, 2026-09-21): команда remote DMA сразу забирает первый байт
    в FIFO, и всё, что происходит между командой и первым циклом данных,
    может оставить этот байт в FIFO -- пакет читается со сдвигом на байт.
    Вывод там: "arm once, touch nothing, transfer". Для плана это значит две
    вещи: после команды DMA до первого data-port цикла нельзя обращаться к
    регистрам, а фиктивное чтение перед записью опасно -- оставшийся в FIFO
    байт способен сдвинуть последующую передачу.

## 4. Проектные решения

### 4.1 Модель "тип карты"

| Тип | База RAM | TPSR | PSTART | PSTOP | Remote write |
|---|---|---|---|---|---|
| `NE2000` (умолчание) | `0x40` | `0x40` | `0x46` | `0x60` | прямая последовательность |
| `NE1000` | `0x20` | `0x20` | `0x26` | `0x40` | прямая последовательность |

Четыре байта в свободном хвосте зазора `LIBBSS_BASE+0x139..0x13F`
([memmap.inc](../src/include/memmap.inc)) -- `LIBBSS_SIZE` и литеральные
смещения BSS в `src/dll/unetrtl.asm` не меняются:

```
RTL_CARD_FLAGS	EQU LIBBSS_BASE + 0x13C	; bit0 = раскладка NE1000
					; bit7 = значение пришло из NET_RTL_TYPE
RTL_TPSR_PAGE	EQU LIBBSS_BASE + 0x13D
RTL_PSTART_PAGE	EQU LIBBSS_BASE + 0x13E	; PSTART и PSTOP подряд:
RTL_PSTOP_PAGE	EQU LIBBSS_BASE + 0x13F	; хелперы идут по ним через INC HL
```

`RTL.INIT_BASE` заполняет эти байты **всегда**. Менять действующую политику
вправе только `SET_LAYOUT`; кто его зовёт -- решает прикладной код.

### 4.2 NET.CFG: ключ `RTL_TYPE`

```
# Card family = where the packet RAM lives.
#   (empty) / AUTO  NETCFG -i works it out (chip ID, then a RAM probe)
#   NE2000          RTL8019AS and NE2000 clones, RAM at 0x4000
#   NE1000          8-bit NE1000 cards, RAM at 0x2000
RTL_TYPE=
```

В файле регистр букв не важен; `NETCFG` приводит к канону. Неизвестное слово
= AUTO + предупреждение. Явное значение отключает пробу. Мастер пишет AUTO
пустой строкой.

### 4.3 Контракт переменной и статус `INIT_BASE`

Значение всегда каноническое: ровно `NE1000` или `NE2000`.
`RTL.READ_CARD_TYPE` сравнивает **всю** строку, включая завершающий нуль.

| Состояние `NET_RTL_TYPE` | `INIT_BASE` |
|---|---|
| отсутствует / пустая строка | NE2000, bit7=0 |
| `NE2000` / `NE1000` | соответствующая раскладка, bit7=1 |
| любое другое | раскладка **не выбирается**, `CF=1`, `A=RTL_INIT_BAD_TYPE` |

`INIT_BASE` не печатает и не завершает процесс по этой причине. Контракт
возврата: `CF=0` -- успех; `CF=1`, `A` = `RTL_INIT_NO_CHIP` (1) или
`RTL_INIT_BAD_TYPE` (2). Вносится в спецификацию SDK (N0).

Прикладная обёртка -- существующий `UTIL.EXIT_NO_NIC` (почти все утилиты уже
делают `JP C,@UTIL.EXIT_NO_NIC`, `A` до него доживает): `BAD_TYPE` ->
сообщение и код 4, иначе как сейчас (код 2). `NETENV._MISSING` превращается в
процедуру `NETENV.DIE_BAD_VAR` (вход `HL` = имя; "`[E] env var <NAME> missing
or invalid; run NETCFG -i`", код 4); `REQUIRE_IP`/`REQUIRE_MAC` переходят на
неё. В утилитах без `USE_NETENV` -- короткое локальное сообщение. Утилиты с
собственной обработкой `CF=1` (`NICINFO`, `NICMODE`, `NETCFG`, `DLDIRECT`,
`WGET` -- проверить все 20 вызовов) дорабатываются по месту. DLL: любой
`CF=1` -> `NERR_NONET`.

Правила публикации:

1. Публикуют только `NETCFG -i` и `IFUP`, и только однозначный результат.
2. Утилиты вне `NETCFG`/`IFUP` пробу RAM не выполняют. Исключение (Q1) --
   `NICINFO`: сверка только на печать.
3. `NETCFG` (показ) печатает переменную, `NETCFG -d` удаляет её.
4. Каждая операция с переменной проверяется, включая удаление: статус DSS
   плюс чтение назад. Итог оценивается по **конечному состоянию** (`final`)
   против намерения (`want`):

| `want` | `final` | Итог |
|---|---|---|
| `NE1000` | `NE1000` | успех |
| `NE2000` | `NE2000` | успех |
| `NE2000` | отсутствует | предупреждение: умолчание совпадает |
| отсутствует (результат неоднозначен) | отсутствует | успех |
| отсутствует | `NE2000` | предупреждение: раскладка совпадает с запасной |
| любое иное сочетание | | **фатально**, код 4, печать `want` и `final` |

5. Порядок в `NETCFG -i`: при явном `RTL_TYPE` публикация идёт до первого
   обращения к железу. При AUTO старая переменная удаляется до пробы.
6. **Граница независимости AUTO от старого значения.** Сама проба от
   переменной не зависит, но ей предшествует `INIT_BASE`, а он отвергает
   недопустимое значение. Поэтому:
   - осталось **допустимое** старое значение (удаление отказало): проба
     идёт, итог решает правило 4 -- если проба подтвердила то же значение,
     это успех;
   - осталось **недопустимое** значение (`XX1`) и удалить его не удалось:
     `NETCFG -i` завершается **до обращения к карте**, код 4, с печатью
     оставшегося значения. Отдельный путь инициализации базы в обход типа не
     заводится: отказ безопасен, а мусор, который нельзя убрать, правило 4
     всё равно признало бы фатальным.

### 4.4 Remote write

Во всех трёх путях записи порядок одинаков:

```
отмена прежней DMA -> очистка RDC -> RBCR/RSAR настоящей записи
  -> команда remote write -> немедленно данные через data port
```

Между командой и первым циклом data port нет чтений регистров, пауз или
фиктивной DMA. Ошибка передачи определяется существующим таймаутом RDC и,
для TX, проверкой загруженного префикса. Отдельной процедуры `WR_PREP`, бита
режима и класса ошибки подготовки нет.

### 4.5 Определение типа

Новая библиотека `src/lib/rtl_detect.asm`, `MODULE RTLDET`, под
`USE_RTL_DETECT`. Подключают только `NETCFG`, `IFUP` и `NICINFO`. В DLL не
входит. Внутри ни одного DSS/BIOS-вызова.

**Два разных понятия** (в редакции 4 они были слиты в одно "QUIESCE"):

- *Режим пробы* -- свойство конфигурации, а не бита STP: приём отключён
  (`RCR.MON`), передача изолирована (`TCR` = internal loopback), прерывания
  NIC запрещены (`IMR=0`), `DCR=0x48`. Внутри него примитивы
  `DMA_READ`/`DMA_WRITE` **запускают** контроллер -- их команды несут STA -- и
  после успеха оставляют `CR=0x22`. Это нормально и режима не нарушает.
- *Состояние на выходе* -- контроллер остановлен, и это проверено.

**`RTLDET.ENTER_PROBE_MODE`** -- вход в режим пробы:

```
CR=0x21, DCR=0x48, RBCR0/1=0, RCR=0x20 (monitor), TCR=0x02 (loopback),
ISR<-0xFF, IMR=0
```

Обязателен перед любой remote DMA **диагностической фазы** -- пробы типа и
чтения PROM -- в `NETCFG`, `IFUP`, `NICINFO`, включая чтение PROM при явно
заданном типе. К рабочему обмену требование не относится: в `IFUP`
диагностическая фаза заканчивается `STOP_AND_CHECK`, затем `INIT_NORMAL`
ставит рабочие `RCR`/`TCR`, и DHCP идёт как обычно. `ISR<-0xFF` -- это
запись, а не утверждение о результате: `ISR.RST` остаётся установленным,
пока чип остановлен (2.5).

**`RTLDET.STOP_AND_CHECK`** -- единый выход диагностической фазы:
`CR<-0x21`, `RBCR0/1<-0`, `ISR<-0xFF`, затем `CHECK_STOPPED`. Выход: `CF=0`
-- остановка подтверждена, `CF=1` -- нет. Им заканчиваются `DETECT` при
**любом** результате, включая короткий путь по Realtek ID, и чтение PROM:
успешная DMA оставляет чип запущенным, так что остановка нужна не только
после ошибки.

**Проверка "чип жив и остановлен" (`RTLDET.CHECK_STOPPED`)**, с явными
масками:

```
CR  : (CR  & 0xD9) == 0x01    PS1,PS0 = 00; RD1,RD0 = 00; STP = 1
                              игнорируются: STA (может остаться, 2.5),
                              RD2 и TXP (сбрасываются сами)
ISR : (ISR & 0x7F) == 0x00    RST игнорируется (только статус)
```

Чтение обусловленное и двойное, как в `SELECT_PAGE`. `0xFF` (плавающая
шина) и `0x00` (мёртвый чип) проверку не проходят; `0x21` и `0x23` --
проходят.

**`RTLDET.DETECT`**. Предусловие: `INIT_BASE` + `RESET` +
`ENTER_PROBE_MODE`.

```
0. Сохранить RTL_CARD_FLAGS; при ЛЮБОМ выходе восстановить. Детектор только
   возвращает результат; политику меняет вызывающий через SET_LAYOUT.
1. RTL_CHIP_KIND == REALTEK -> результат NE2000, источник "ID", проб нет;
   переход к шагу 5.
2. Иначе выполнить probe(0x40), затем probe(0x20). probe(P), два прохода с
   разными образцами:
     DMA_WRITE 8 байт образца      по адресу  P   * 256
     DMA_WRITE 8 байт инверсии     по адресу (P+1)* 256
     DMA_READ  оба блока
   Статус пробы: OK | MISMATCH | UNSTABLE (проходы разошлись) | TIMEOUT.
3. CF=1 от любого примитива (таймаут RDC):
     а) СНИМОК -- первым действием, до любой записи в чип: стадия, адрес
        пробы, CR, ISR, CRDA0/1. Примитивы за собой не чистили (4.4),
        поэтому это подлинное состояние отказа; по CR видно направление DMA.
     б) STOP_AND_CHECK:
        прошёл     -> результат DMA_ERROR;
        не прошёл  -> результат CHIP_FAULT.
   Вторая проба после отказа НЕ выполняется. Выход (шаг 5 уже сделан).
4. Сведение статусов -- таблица ниже.
5. ОБЩИЙ ВЫХОД для NE1000, NE2000 (в т.ч. по Realtek ID), AMBIGUOUS, UNKNOWN:
   STOP_AND_CHECK. Не прошёл -> результат заменяется на CHIP_FAULT: пробы
   прошли, но чип перестал отвечать -- доверять их итогу нельзя.
```

| probe(0x40) | probe(0x20) | Результат |
|---|---|---|
| OK | MISMATCH | `NE2000` |
| MISMATCH | OK | `NE1000` |
| OK | OK | `AMBIGUOUS` |
| MISMATCH | MISMATCH | `UNKNOWN` |
| UNSTABLE в любой | -- | `UNKNOWN` |
| отказ, контроль прошёл | не выполнялась | `DMA_ERROR` |
| отказ, контроль не прошёл | не выполнялась | `CHIP_FAULT` |

**Состояние на выходе.** `RTL_CARD_FLAGS` -- как на входе, всегда. Для всех
результатов, кроме `CHIP_FAULT`, чип **подтверждённо остановлен**
(`STOP_AND_CHECK` прошёл), а конфигурация режима пробы (`RCR`/`TCR`/`IMR`)
сохранена -- следующая DMA диагностической фазы (чтение PROM) может идти без
повторного входа. При `CHIP_FAULT` состояние чипа **не подтверждено** и
постусловием не является: вызывающий обязан прекратить обращения к карте. BSS детектора -- в `memmap.inc`; кандидат `0xAF00`,
проверить на свободность одновременно в `NETCFG`, `IFUP`, `NICINFO`.

**Что делает вызывающий.** `NETCFG` -- публикатор конфигурации, `IFUP` -- тот,
кто объявляет интерфейс поднятым.

| Результат | Раскладка | `want` (4.3) | `NETCFG -i` | `IFUP` |
|---|---|---|---|---|
| `NE1000` | NE1000 | `NE1000` | `card type: NE1000 (auto: RAM at 2000)` | то же, продолжает |
| `NE2000` | NE2000 | `NE2000` | `card type: NE2000 (auto: RAM at 4000 \| Realtek ID)` | то же, продолжает |
| `AMBIGUOUS` | NE2000 (запасная) | отсутствует | `[W05]`, код без изменений | `[W05]`, продолжает |
| `UNKNOWN` | NE2000 (запасная) | отсутствует | `[W04]` + статусы проб | `[W04]`, продолжает |
| `DMA_ERROR` | NE2000 (запасная) | отсутствует | `[W07]` + снимок; чтение PROM всё равно пробуется | **`[E07]`, код 3, `NET=RTL` не публикуется** |
| `CHIP_FAULT` | -- | отсутствует | `[E08]` + снимок, обращений к карте больше нет; код 3, если нужен был MAC из PROM | **`[E08]`, код 3, `NET=RTL` не публикуется** |
| карта недоступна | -- | отсутствует | существующий `[E2]` | существующий путь |
| явный `RTL_TYPE` | как задано | как задано | `card type: NE1000 (NET.CFG)` | пробы нет |

`IFUP` строже и для `DMA_ERROR` с подтверждённой очисткой: каждая передача
-- remote write, а статический `IFUP` пакетами не обменивается (3.11).
Выход для клона, который не переносит только саму пробу, -- `RTL_TYPE=`.

Сообщения:

```
[W04] card type not detected (4000:<st> 2000:<st>), assuming NE2000; set RTL_TYPE
[W05] packet RAM answers at both 2000 and 4000, assuming NE2000; set RTL_TYPE
[W06] NET_RTL_TYPE says NE2000 but the RAM probe says NE1000; run NETCFG -i
[W07] card type probe: remote DMA did not complete, assuming NE2000   (NETCFG)
[E07] remote DMA does not complete; interface NOT up                  (IFUP)
[E08] chip not responding after DMA abort
```

Поток в `NETCFG -i` (`PROBE_CARD` вместо `FILL_MAC_FROM_PROM`):

```
нужно железо = (MAC пуст) ИЛИ (RTL_TYPE = AUTO)
если нужно:  [ранний выход по 4.3.6] -> INIT_BASE -> RESET
             -> ENTER_PROBE_MODE
             -> [DETECT, если AUTO; сам заканчивается STOP_AND_CHECK]
             -> SET_LAYOUT
             -> [PROM MAC, если пуст и не CHIP_FAULT] -> STOP_AND_CHECK
             -> ISA_CLOSE -> печать -> SETENV с проверкой
```

`IFUP`: если `RTL_CARD_FLAGS.7=0` -- после `RESET`: `ENTER_PROBE_MODE` ->
`DETECT` -> `SET_LAYOUT` -> `ISA_CLOSE` -> по таблице -> `ISA_OPEN` ->
`INIT_NORMAL`. На этом диагностическая фаза кончилась; дальнейший DHCP-обмен
идёт в рабочем режиме и под требование о режиме пробы не подпадает.

Почему адреса `0x4000` и `0x2000`: при неполной дешифрации NE1000 зеркалит
RAM на `0x6000/0xA000/0xE000`, но не на `0x4000`; NE2000 -- на `0xC000`, но
не на `0x2000`. Обе пробные страницы лежат в TX-области, вне кольца RX.

### 4.6 Драйвер

- `rtl8019.inc`: `RTL_*_INIT` -> `RTL_RAM_BASE_NE2000=0x40`,
  `RTL_RAM_BASE_NE1000=0x20`, `RTL_TX_PAGES=6`, `RTL_RAM_PAGES=0x20`;
  `RTL_INIT_NO_CHIP`, `RTL_INIT_BAD_TYPE`. `RTL_ALT_TX_LAYOUT` -- смещения от
  базы.
- `RTL.SET_LAYOUT`, `RTL.READ_CARD_TYPE` -- 4.1, 4.3.
- **`SELECT_PAGE` и DP8390 (3.17).** Сверка записанного STOP-значения не
  должна требовать STA=0. Нейтральный по размеру вариант --
  `CR_VERIFY_MASK = 0xC1` (страница + STP): драйвер пишет только состояния
  "STP=1" и "STP=0, STA=1", их различает один бит STP, так что STA в маске
  информации не добавляет. Маска влияет только на сравнение, обращения к
  чипу не меняются -- журнал NE2000 остаётся идентичным. Комментарий про
  совпадение диапазона кольца под маской обновить для обеих раскладок.
- **Аудит всех сверок `CR`, а не одной константы.** Их в дереве три:
  `SELECT_PAGE`, `NICREG`:1488 (обе через `CR_VERIFY_MASK`) и запись `CR` в
  `G3_TABLE` `NICREG` со своей маской `0xFF` (3.17). Последнюю общая
  константа не исправит: маска G3 меняется на `0xFD` -- исключается только
  STA, остальная строгость этой фазы сохраняется.
- Точки использования: `LD (IX+d),n` -> `LD A,(var)` + `LD (IX+d),A`;
  сравнения -- `LD HL,RTL_PSTART_PAGE` / `CP (HL)` / `INC HL`; 16-битные
  формы собираются из байта.
- Сокращение числа точек: `NEXT_RX_PAGE_A`; проверка `CURR` в
  `RING_HAS_PACKET` -> `VALID_RX_PAGE_A`. Хелперы сохраняют `BC`/`DE`.
- Гейты мёртвого кода: `SNAPSHOT_REGS` -- под `IFNDEF UNET_DLL`;
  `PROBE_ID`, `READ_PROM`, `PROBE_PRESENT` -- под `USE_RTL_<name>`.

### 4.9 Разбор PROM: `RTLDET.DECODE_PROM_MAC`

Заменяет оба нынешних алгоритма. Принцип: **выбирается единственное
прочтение, согласное с документированным форматом PROM семейства NE**
(сигнатура `57h` либо `42h` в логических байтах 14 и 15). Если согласны оба
прочтения или ни одно, нужно внешнее свидетельство; без него -- честное
"неоднозначно". Эвристик по содержимому заполнителя нет.

Вход: 32 байта `P[0..31]` (байтовый режим, адрес 0) и тип карты `T`
(`NE1000`, `NE2000` либо "не определён"). PROM читается **дважды**;
расхождение чтений -> повтор, затем ошибка NIC (код 3): однократный сбой
чтения превращает удвоенный PROM в "прямой".

```
pairs = P[2i] == P[2i+1] для всех i = 0..15   (необходимо для DOUBLED)
sigD  = P[14] == P[15] и P[14] из {57h, 42h}  (сигнатура на месте DIRECT)
sigX  = P[28] == P[30] и P[28] из {57h, 42h}  (сигнатура на месте DOUBLED)
```

Кандидаты: `DIRECT` -> MAC = `P[0..5]`; `DOUBLED` -> MAC =
`P[0],P[2],..,P[10]`.

| # | Условие | Итог | Обоснование |
|---|---|---|---|
| 1 | не `pairs` | `DIRECT` | удвоенное прочтение невозможно |
| 2 | `pairs`, `sigD`, не `sigX` | `DIRECT` | у удвоенного PROM сигнатура обязана стоять в `P[28..31]`; её там нет -- удвоенное прочтение не согласно с форматом |
| 3 | `pairs`, `sigX`, не `sigD`, `T` <> `NE1000` | `DOUBLED` | симметрично: прямое прочтение не согласно с форматом |
| 4 | `pairs`, `sigX`, не `sigD`, `T = NE1000` | `AMBIGUOUS` | свидетельства противоречат друг другу |
| 5 | `pairs`, (`sigD` и `sigX`) либо (ни одной), `T = NE1000` | `DIRECT` | документированное свойство: у 8-битной карты адрес PROM идёт за адресом DMA 1:1, удвоения нет (так выбирает формат FreeBSD) |
| 6 | то же, совпал **подтверждённый аппаратный профиль** | формат профиля | см. ниже |
| 7 | иначе | `AMBIGUOUS` | оба прочтения согласны с форматом (или оба нет), внешних свидетельств нет |

**Таблица профилей изначально пуста.** Запись добавляется только по
измерению на реальной карте, занесённому в `docs/evidence/` (N8), и
ключуется тем, что драйвер действительно знает: вид чипа (`RTL_CHIP_KIND`),
байт сигнатуры, тип карты. Первый кандидат на проверку -- настоящий
RTL8019AS в слоте ISA-8: до измерения для него профиля нет.

При `AMBIGUOUS` печатаются оба кандидата, MAC не публикуется, код 4,
требование `RTL_MAC=` -- тот же путь, что сейчас для нулевого MAC. Сигнатура
вне `{57h,42h}` при исходе `DIRECT` по правилу 1 -- отдельное `WARN`, как
сегодня (сигнатура -- проверка здравости, не затвор).

Опорные случаи:

- Прямой 16-байтовый PROM, MAC `00:00:11:11:22:22`, заполнитель `57`, хвост
  `FF`: правило 2, `DIRECT`, MAC верный.
- Контрпример ревью 3 -- `00 00 11 11 22 22 33 33 44 44 55 55 57 57 57 57`,
  хвост `57`: `pairs`, `sigD` и `sigX`. Прочтения `00:00:11:11:22:22` и
  `00:11:22:33:44:55` оба согласны с форматом. На NE1000 -- правило 5,
  `DIRECT`; иначе правило 7, `AMBIGUOUS`. Правило "неравномерный
  заполнитель -> DOUBLED" из редакции 3 снято: оно молча выбирало второй MAC.
- MAME `rtl8019as`, конфигурация по умолчанию (**прямой** PROM, заполнитель
  `57`, случайный MAC): не `pairs` -> правило 1. Основной стенд не затронут.
- MAME `rtl8019as` с опцией "PROM layout = doubled" (заполнитель `57`):
  `pairs`, `sigD` и `sigX` -> правило 7, `AMBIGUOUS`. Это честный результат:
  эти 32 байта побайтно совпадают с контрпримером. Для такого стенда --
  `RTL_MAC=` либо конфигурация по умолчанию; записать в `MAME_NETWORK.md`.
- Харнесс `promLayout: 'doubled'` (заполнитель `00`): `sigX`, не `sigD` ->
  правило 3, существующие тесты не меняются.
- UM9003AF в ISA-8 (прямой `BB`, MAC `00:00:01:06:87:81`): правило 1.
- MAME `ne1000`, MAC `00:00:1B:xx:yy:zz`: как правило не `pairs` -> правило 1
  (сегодняшний `NETCFG` здесь ошибается).

После выбора формата MAC отвергается, если он нулевой, широковещательный
или с битом multicast -- код 4 и требование `RTL_MAC=`.

`NICINFO` передаёт в `T` результат своей сверочной пробы, если он однозначен,
иначе тип из окружения, и печатает, какой `T` использован.

### 4.10 Где виден тип и его источник

- **Раскладка** видна на любом сбое сетевых утилит без единой правки: дамп
  регистров читает `PSTART/PSTOP` с железа. `26/40` -- NE1000, `46/60` --
  NE2000.
- **Источник** значения показывают только `NETCFG` и `NICINFO`.
- **DLL**: `LASTERR` и `GETINFO` не меняются; фиксируется в `UNETRTL.md`.

### 4.11 Отвергнутые варианты

- Выбор раскладки RAM по PROM `WW`/`BB` (2.3); проба RAM в каждой утилите;
  тип внутри `NET_RTL_HW`; отдельные сборки под NE1000.
- Разбор `NET_RTL_TYPE` по одному символу (ревью 1).
- `DSS_EXIT` из `INIT_BASE`; "сбой публикации NE2000 -- лишь предупреждение";
  правило PROM "удвоен, если равны все пары" (ревью 2).
- Правила PROM "неравномерный заполнитель -> DOUBLED" и "завёрнутый хвост ->
  DIRECT"; сверка `CR` "как записан" после STP; очистка DMA внутри
  примитивов при отказе; задержка предвыборки в обращениях к регистрам
  (ревью 3).
- Единое понятие "QUIESCE" для режима пробы и состояния остановки; очистка
  только на пути ошибки; готовность подготовки, проверяемая лишь к моменту
  команды записи; задержка предвыборки "любая ненулевая"; исправление сверки
  `CR` одной общей константой (ревью 4).
- `WR_PREP` безусловно для всех карт -- меняет последовательности на
  работающих RTL8019AS/UM9003. `WR_PREP` только после сбоя
  `VERIFY_TX_PREFIX` -- зависимость по кругу.

### N1. Харнесс: модель NE1000
- `quirks.variant: 'NE1000'`: RAM 8 КБ на `0x2000..0x3FFF`, PROM прямой 16
  байт `WW` с MAC `00:00:1B:..`, за пределами PROM `FF`, ID не `Pp`,
  страницы 3 нет, **семантика DP8390 по умолчанию**: `staSticksOnStop` (после
  STP у запускавшегося чипа читаются STP и STA; признак "запускался" снимает
  только аппаратный сброс, программный -- нет) и `rstStatusOnly` (`ISR.RST`
  не сбрасывается записью, снимается командой START). Опция сценария
  `chipPreStarted` -- чип уже работал в этой сессии (`CR=0x22`), как при
  запуске второй утилиты подряд.
- `remoteDmaStall` моделирует отсутствие RDC после передачи;
  `chipDeadAfterStall` -- переставший отвечать контроллер.
- Прочие причуды: `ramMirror`, `floatingLocalBus`, `chipDeadAfterStall`
  (после отказа CR читается как `FF` -- путь `CHIP_FAULT`), `unstableRam` и
  PROM-варианты из 6.5.
- **Два режима проверки адресов:**
  - *строгий* (`strictRam: true`): любой local/remote DMA вне окна RAM --
    исключение, кроме двух узких разрешений:
    1. чтение PROM: только remote **read**, адреса `0x0000..0x001F`, длина
       <= 32;
    2. проба типа: только remote DMA, длина <= 8, адреса ровно `P*256` и
       `(P+1)*256` для `P` из {`0x20`,`0x40`}, только в **режиме пробы** --
       `RCR.MON` установлен, `TCR` = loopback, `IMR=0`. Бит STP в условие
       не входит: во время самой передачи примитив уже поставил STA (4.5).
  - *аппаратный* (`strictRam: false`): вне RAM чтение отдаёт PROM/open bus,
    запись игнорируется -- для отрицательных тестов.
- `scenario.traceChip`; отказ окружения по имени и виду операции
  (`envFail: {name, op: 'delete'|'replace'|'create'}`).

Для каждой строки с отказом проверяются **содержимое снимка и порядок
обращений**, а не только наличие `[W07]`: в журнале после отказавшего
обращения идут чтения `CR`, `ISR`, `CRDA0`, `CRDA1` и лишь затем запись
`CR<-0x21`; в снимке `CR` несёт взведённую команду remote DMA (не `0x21`),
`ISR` -- без RDC. Для всех строк: нет бесконечных ожиданий, нет DSS-вызовов
при открытом ISA, `RTL_CARD_FLAGS` после `DETECT` равен значению до него.

**Состояние на выходе проверяется для каждого результата, а не только для
отказов:** после `NE1000`, `NE2000` (включая путь по Realtek ID),
`AMBIGUOUS` и `UNKNOWN` последними обращениями `DETECT` в журнале идут
`CR<-0x21`, `RBCR<-0`, `ISR<-0xFF` и чтения `CHECK_STOPPED`; модель
подтверждает, что чип остановлен, а `RCR.MON`/`TCR`/`IMR` режима пробы
сохранены. Успешная DMA оставляет `CR=0x22`, так что без общего выхода эта
проверка красная.

| remote read 1 байта | отдан байт по `RSAR` (не `RSAR+1`); одно обращение к data port; RDC; `CRDA = RSAR+1` |
| remote read 2 байт | первый и последний байт верны; два обращения; RDC после второго |
| remote read 32 байт (как PROM) | первый и последний байт верны; 32 обращения; RDC; `CRDA = RSAR+32` |
| лишнее обращение к data port после RDC | учитывается как `strayDma`, как сейчас |
| `chipPreStarted` + `CR<-0x21` | читается `0x23`; после аппаратного сброса и `CR<-0x21` -- `0x21` |
| `rstStatusOnly`: `ISR<-0xFF` в остановленном чипе | читается `0x80`; после START -- `0x00` |
| весь существующий набор на вариантах `RTL8019AS`/`UM9003` | без изменений: новые свойства включены только там, где заданы |

## 7. Риски, решения, история

### 7.1 Риски

| # | Риск | Мера |
|---|---|---|
| R1 | Не хватит байт в **DLL** | 4.7: фактический размер проверяется ASSERT и сборкой |
| R2 | Отдельным клонам всё же нужен обход remote-write erratum | Сначала подтвердить на реальной карте; не менять общую модель MAME и рабочие карты без измерения |
| R3 | Проба на UM9003/клонах даёт `AMBIGUOUS` | `UNKNOWN`, `[W04]` и запасная NE2000; `RTL_TYPE=NE2000` отключает пробу |
| R4 | Настоящая NE1000 зеркалит RAM на `0x4000` | `AMBIGUOUS` -> `RTL_TYPE=NE1000` |
| R5 | Reset-порт `BASE+0x1F` на NE1000 | AUTO даёт SOFT; `RTL_RESET=HARD` -- вручную |
| R6 | MAME `ne1000` расходится с железом | Причуды модели покрывают оба поведения; истина -- N8 |
| R7 | Диагностика, запущенная до `NETCFG -i`, тестирует не ту RAM | `NICINFO` сверяет окружение с пробой (`[W06]`) |
| R8 | Ложный `DMA_ERROR` на работающей карте теперь валит `IFUP` | Возможен только когда клон не переносит саму пробу; лекарство -- `RTL_TYPE=` |
| R9 | Строгий разбор PROM чаще требует `RTL_MAC=` (удвоенный PROM с заполнителем, равным сигнатуре, на не-NE1000 карте) | Известные карты мейнтейнера не затронуты (правила 1, 2, 5); таблица профилей пополняется по измерениям |
| R10 | Поведение `CR`/`ISR` на настоящем DP8390 отличается и от описанного в 2.5 | Маски `CHECK_STOPPED` и `SELECT_PAGE` проверяются на N8 до остального |

### 7.2 Решения мейнтейнера (2026-09-21)

- **Q1 -- разрешено.** `NICINFO` выполняет сверочную пробу только на печать.
- **Q2 -- не включаем.** Авто-скан баз принимает только ID Realtek.
- **Q3 -- `0.4.0`**, в шаге N9.

### 7.3 Ревью 1 (редакция 1 -> 2) -- все замечания приняты

Эрратум remote write до детектора; контракт ошибок детектора; параметризация
диагностик вместе с драйвером; признак конца таблицы `NICRAM` и `0x5A00`;
два режима модели; бюджет и отказ от переноса `LASTERR`; разбор переменной
полной строкой; порядок первого запуска в MAME; `QUIESCE` для чтения PROM;
сценарии повторного `NETCFG -i`; проверки MAC; коммиты N2a/b/c; где виден
тип.

### 7.4 Ревью 2 (редакция 2 -> 3) -- все замечания приняты

Третий путь записи (G6 в `NICREG`); проверяемые удаление и публикация,
правило конечного состояния; формальный разбор PROM с `AMBIGUOUS`; `DETECT`
восстанавливает флаги; предвыборка NIC в модели и разрешения строгого
режима; `DMA_ERROR`/`CHIP_FAULT` фатальны для `IFUP`; `INIT_BASE` возвращает
статус; повторная проба в мастере; диагностика таймаута до очистки; пересчёт
бюджета `WR_PREP`; восемь пробных записей.

### 7.5 Ревью 3 (редакция 3 -> 4) -- все замечания приняты

1. Сверка `CR` после STP: STA может остаться, `ISR.RST` записью не
   сбрасывается -> 2.5, `CHECK_STOPPED` с явными масками (4.5), тест
   исправного контроллера (6.1). При `CHIP_FAULT` состояние `QUIESCE` --
   неподтверждённое, а не постусловие. **Найдено дополнительно:** та же
   особенность ломает существующий `SELECT_PAGE` (маска `0xC3` включает STA)
   и сверку в `NICREG` -> 3.17, 4.6, N3.
2. Снимок до первой очистки: ответственный один -- вызывающий; примитивы при
   отказе не чистят и регистров не трогают -> 4.4, 4.5; тест проверяет
   содержимое снимка и порядок обращений (6.1).
3. Модель времени: задержка предвыборки в тактах CPU; `prefetchStall` (отказ
   подготовки) отделён от `remoteDmaStall` (отказ передачи); ворота N3
   переписаны, в том числе для варианта без проверки -> N1, N3.
4. PROM: правило "неравномерный заполнитель" снято как эвристика; остался
   принцип единственного прочтения, согласного с документированным форматом,
   плюс пустая таблица подтверждённых профилей -> 4.9, 6.5. **Исправлена
   собственная ошибка редакции 3:** MAME `rtl8019as` по умолчанию отдаёт
   прямой PROM; удвоенный -- опция конфигурации (2.2).
5. Граница независимости AUTO: недопустимое неудаляемое значение -> ранний
   выход с кодом 4 до обращения к карте -> 4.3.6, 6.4.

### 7.6 Ревью 4 (редакция 4 -> 5) -- все замечания приняты

1. Вторая сверка `CR` в `NICREG` -- `G3_TABLE` со своей маской `0xFF`,
   которую `CR_VERIFY_MASK` не затрагивает -> 3.17, 4.6 (аудит всех трёх
   сверок), тест на уже работавшем контроллере с проверкой именно строки G3
   (N3). Попутно проверено, что остальные `CP 0x21` в дереве к `CR` не
   относятся.
2. Порядок подготовки: дождаться предвыборки нужно до перепрограммирования
   `RBCR`/`RSAR`, а не до команды записи -> 2.4, 4.4 (единый порядок для трёх
   путей, место вызова в `DMA_WRITE` и G6); модель фиксирует нарушение в
   момент записи параметров; временные границы заданы числами, журнал несёт
   метки тактов -> N1, N3, 6.7.
3. Режим пробы отделён от состояния остановки: `ENTER_PROBE_MODE` и общий
   выход `STOP_AND_CHECK` для **всех** результатов, включая путь по Realtek
   ID; разрешение строгой модели привязано к `RCR.MON`/`TCR`/`IMR`, а не к
   STP; требование относится к диагностической фазе, DHCP-обмен `IFUP` им не
   затронут -> 4.5, N1, 6.1, 6.6.

Дополнение: буфер предвыборки в модели и её самопроверки на 1, 2 и 32 байтах
-> N1, 6.7. **Найдено при проверке:** комментарий к `G6_DMA_START` содержит
измерение на UM9003AF о байте, остающемся в FIFO после взвода; оно
подтверждает обязательность порядка из п. 2 и делает риск R3 измеримым ->
3.18, R3, причуда `staleFifoAfterDummyRead`.

### 7.7 Коррекция после реализации (редакция 5 -> 6)

Пункты истории 7.3-7.6 выше описывают ход прежних ревью и не являются
действующими требованиями к remote write. Проверка рабочего
`NE2000.COM` v11.4.3 показала прямую запись без подготовительного чтения;
исходники Crynwr NE1000/NE2000 подтверждают тот же порядок. Опциональный
Linux `NE_RW_BUGFIX` выключен по умолчанию и прямо отмечен как ненадёжный.
Принято решение удалить `WR_PREP`, связанные причуды тестовой модели и
локальную правку общего устройства DP8390 в MAME. Действующая спецификация --
2.4 и 4.4 редакции 6.

## 9. Критерии готовности

- Один и тот же `distr/sprinter-rtl8019a.img` работает в MAME с
  `-isa1 rtl8019as` и с `-isa1 ne1000`; различается только `NET.CFG`.
- На NE1000: `NETCFG -i` с пустым `RTL_TYPE` публикует `NET_RTL_TYPE=NE1000`
  и верный MAC; `NICINFO` видит карту; `NICRAM` проходит все девять случаев;
  `NICREG` проходит G6 без ложных потерь записи; `PING`, `UDPTEST`, `TFTP`,
  `NTP`, `WGET` (2/24/56 КБ), `FTP` (passive), `TELNET`, `UNETTEST` через DLL
  -- `RESULT OK`.
- На RTL8019AS и UM9003AF поведение не изменилось: AUTO даёт NE2000, журнал
  обращений к чипу в рабочих путях идентичен прежнему.
- Ни одна утилита, кроме `NETCFG`/`IFUP` и сверки в `NICINFO`, не выполняет
  пробу RAM; только `NETCFG`/`IFUP` публикуют `NET_RTL_TYPE`, лишь
  однозначный результат, с проверкой конечного состояния переменной.
- Недопустимое значение `NET_RTL_TYPE` не выбирает никакую раскладку;
  `RTL.INIT_BASE` сообщает о нём статусом, не завершая процесс.
- `IFUP` никогда не объявляет интерфейс поднятым после отказа remote DMA.
- Исправный DP8390 с оставшимся после STP битом STA и несбрасываемым
  `ISR.RST` не объявляется неисправным -- ни детектором, ни `SELECT_PAGE`,
  ни `NICREG` (включая строку `CR` фазы G3), в том числе при запуске второй
  утилиты в той же сессии.
- Во всех трёх путях записи после команды remote write сразу идут циклы
  data port; фиктивной DMA и промежуточного опроса регистров нет.
- Диагностическая фаза при любом исходе, кроме `CHIP_FAULT`, заканчивается
  подтверждённо остановленным чипом; рабочий обмен `IFUP` идёт вне режима
  пробы.
- Диагностика отказа DMA показывает состояние **до** очистки.
- Неоднозначный PROM не даёт молчаливо неверного MAC.
- `UNETRTL.DLL` и `TELNET.EXE` проходят `ASSERT` размера с порогами 4.7.
- `make test-host package image` зелёный; имена 8.3 и ASCII в `distr/` не
  нарушены.
- Диагностика по одному скриншоту -- в объёме 4.10.
- Пакет выпущен как `0.4.0`.
