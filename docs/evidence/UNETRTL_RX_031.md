# UNETRTL 0.3.1: сохранение TCP payload до ACK

Дата: 2026-09-11. Автоматические проверки выполнены; MAME/реальная карта
и исходный SNC/WebDAV пока не проверены. Этот документ не входит в пакет.

## Воспроизведение на исходной DLL

- 0.3.0, 18084 байта.
- SHA-256: `e7ac90117786e453c916c67da2af139c1bc7b58d946547b375bdf6f13b43044f`.
- Новый `UNETTEST -r 0 192.168.7.1 8080` на этой DLL падает в сценарии
  `mss=1460, combinedAck=true, finWithData=false`: exit 3, `RESULT FAIL`.
  LOST выявляется до побайтной проверки: длина/CRC в отчёте равны нулю.
- Проверка сначала воспроизведена до изменения TCP/DLL, затем повторена
  с сохранённой исходной DLL после реализации.
- 1460 превышает объявленный MSS 536. Это защитная регрессия для нарушения
  порядка сохранения/ACK, а не доказательство именно такой сегментации SNC.

## Автоматическая приёмка

`make test-host package image` проходит: 64 NIC/EXE + 100 protocol +
31 TCP + 42 DLL = 237 проверок, тест старого TCP-probe и два теста нового
socket-сервера. ZIP и FAT12-образ пересобраны. Существующее предупреждение
об отсутствии LICENSE остаётся; оно не относится к исправлению TCP.

- ZIP SHA-256: `a11393a5cadfbed6662437302c91617fb5483efcdc93614176a29adbe373dffc`.
- IMG SHA-256: `f87b73919df6f951cbef2a07e05c9b3053b9d5e5a7daa5b87500eaceb3bb3936`.

Матрица полного ответа: blocking/sliced SEND с реальным NERR_AGAIN,
отдельный/совмещённый ACK, сегменты 536/1460, отдельный FIN/FIN+payload.
Все 16 комбинаций дают 8233 байта, `first8=485454502F312E31`,
`crc32=62763860`, `RESULT OK`.

Дополнительные ABI-проверки: 64-байтовый RECV, полная очередь, повтор с
перекрытием, второй канал и его нулевое/вновь открытое окно, payload до ACK
с последующим AGAIN и чтением pending во время паузы, FIN во время SEND,
сбой ACK после сохранения в SEND и публичном RECV, частичный исходящий ACK
с последующим таймаутом (DE=3), stale/future ACK, релокация в WIN2.
RST с допустимым cumulative ACK возвращает `NERR_CLOSED`, сохраняя в DE
подтверждённый прогресс.

Трассировка: `UNET_TRACE=/tmp/unet-rx.jsonl node tools/test-exe-dll.js`.
JSONL содержит границы публичных вызовов и обработчика сохранения,
sequence/ACK/window, ACK_WAIT_STATE, длины RX/pending, LOST, A/DE/IX и кадры.
Символы берутся из текущего ассемблированного исходника; внутренние снимки
читаются только пока libman отображает DLL.

## Приёмка MAME с pcap

11.09.2026 два запуска через `run_sprinter_rtl8019as.sh` с образом
`distr/sprinter-rtl8019a.img` и сервером `unettest_response_server.py` дали:

```text
DLL: UNETRTL v0.3.1  v0.3
[R1] first8=485454502F312E31
[R2] length=8233 crc32=62763860
resumes needed: 0
RESULT OK
```

Первый запуск сообщил `ping: 45 ms`, второй `ping: 14 ms`; оба завершились
`RESULT OK`. Сервер получил два запроса по 88 байт и напечатал `response
sent` для каждого. `tcpdump` на `feth1` зафиксировал 82 пакета (95 принятых
фильтром, 0 потерянных ядром) в `/tmp/unetrtl-fix.pcap`. Это подтверждает
исправление на сетевом пути MAME. Разбор pcap показывает MSS 536 в SYN,
сегменты ответа по 536 байт, повторную передачу первого сегмента, изменение
окна DSS `536 -> 2049 -> 536`, последний `FIN+193` и итоговый ACK 8235.
