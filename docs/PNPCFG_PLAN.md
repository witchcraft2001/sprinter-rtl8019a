# План: PNPCFG.EXE -- определение и настройка ISA Plug and Play карт

Статус: черновик, редакция 1 от 2026-09-22, к реализации не принят.
Документ только для разработки: в `DIST_DOC_FILES` не добавлять (как
`MAME_NETWORK.md` и `NE1000_PLAN.md`).

## 0. Коротко

- Карта в режиме ISA PnP после включения не отвечает ни по одному адресу I/O,
  пока её не настроит PnP-программа. У Sprinter нет PnP BIOS, поэтому такая
  карта для всего пакета выглядит отсутствующей (`docs/NICEEP.md`).
- `PNPCFG.EXE` выполняет ту часть работы PnP BIOS, которая нужна сетевой
  карте: ключ инициации, изоляцию, назначение CSN, чтение идентификатора и
  ресурсов, затем адрес I/O, "без IRQ" и активацию. После этого карта видна
  драйверу как обычный NE2000 по заданному адресу, и дальше работают
  `NETCFG -i`, `NICINFO`, `NICRAM` и весь стек без изменений.
- Первая поставка -- только чтение (`PNPCFG` без ключей): найти карту и
  напечатать её ID, ничего не активируя. Это одновременно проверка главного
  неподтверждённого вопроса -- доходят ли до слота линии A10/A11, без которых
  карта не увидит порт `0xA79`.
- Настройка энергозависима: она живёт до выключения питания или RSTDRV.
  `PNPCFG -c` запускается при каждой загрузке, до `NETCFG -i`.
- Постоянное переключение карты в режим без PnP (запись 93C46) в рамки не
  входит: политика `NICEEP` -- запись EEPROM только отдельным решением.

## 1. Цель и рамки

Цель: карта ISA PnP (NE2000-совместимая) в слоте ISA-8 Sprinter становится
доступной пакету без PC и без утилиты производителя.

Входит:

- модуль `src/lib/pnp_lib.asm` (SDK-стиль, явные коды статуса, без печати и
  без вызовов DSS) и утилита `src/apps/pnpcfg.asm`;
- режим списка (только чтение) и режим настройки логического устройства;
- модель PnP-карты в host-харнессе, затем проверка на реальной карте;
- документация `docs/PNPCFG.md` (RU + EN), подсказка в `NETCFG -i`/`IFUP`.

Не входит (возможные этапы позже, см. P7):

- запись EEPROM для постоянного режима без PnP;
- вендорные ключи инициации (DM9008 "DM Initiation Key", ключ UMC из
  `RLASET`);
- настройка IRQ, DMA и окон памяти -- пакет работает опросом;
- поддержка `PNPCFG` внутри `UNETRTL.DLL` и сетевых утилит.

## 2. Нужна ли утилита конкретной карте

| Карта / чип | Режим после включения | Нужен PNPCFG |
|---|---|---|
| UM9008F / DM9008, Compex RL2000A-PnP | "Auto-Detection" по умолчанию: *"DM9008 is power-on in jumperless mode"*, в PnP уходит только по ключу | нет, кроме EEPROM с жёстким режимом PnP (байт `0x50` 'P') |
| Intel 82595FX (EtherExpress PRO/10+) | бит 0 слова 0 EEPROM = PnP | да, если бит установлен |
| RTL8019AS | режим задаёт вывод JP и CONFIG в 93C46 | да, если карта в режиме PnP |
| Edimax APX (EN-2000PXA) | режимы PnP / software / jumper | да, в режиме PnP |
| UM9003, W89C904, EN2000N, NE2000 на перемычках | не PnP | нет |

Признак на Sprinter: `ISAPROBE` не находит ни одного живого блока ни по
одному адресу, при этом карта заведомо исправна.

## 3. Протокол ISA PnP (сверено по DM9008-DS-F02, Appendix B)

Источники: спецификация Plug and Play ISA 1.0a; даташит DM9008 (раздел
"Plug and Play (PnP) Module" и Appendix B); как справка -- Linux `isapnp`,
FreeBSD `pnp.c`. Код не импортировать.

- Порты: `ADDRESS` = `0x279` (W), `WRITE_DATA` = `0xA79` (W),
  `READ_DATA` = переносимый, `0x203..0x3FF` (R). Адрес `READ_DATA` задаётся
  записью в регистр `0x00`: биты 7..0 становятся битами 9..2 адреса, биты
  1..0 всегда `11`.
- Состояния карты: Wait for Key -> (ключ) Sleep -> (`Wake[0]`) Isolation ->
  (CSN) Config / Sleep. В Wait for Key карта игнорирует все обращения к
  портам PnP.
- Ключ инициации: две записи `0` в `ADDRESS`, затем 32 байта LFSR
  (`6A B5 DA ED F6 FB 7D BE DF 6F 37 1B 0D 86 C3 61 B0 58 2C 16 8B 45 A2 D1
  E8 74 3A 9D CE E7 73 39`).
- Изоляция: 72 пары чтений из `READ_DATA` (регистр `0x01`). Пара `55 AA`
  означает бит 1, всё остальное -- бит 0. Первые 64 бита -- vendor ID и
  серийный номер, последние 8 -- контрольная сумма LFSR по первым 64.
- Паузы: 2 мс после RSTDRV или PnP Reset до любого обращения; 1 мс перед
  первой парой изоляции; 250 мкс между парами.
- Регистры карты: `0x02` Config Control (бит 0 reset, бит 1 Wait for Key,
  бит 2 reset CSN), `0x03` Wake[CSN], `0x04` Resource Data, `0x05` Status
  (бит 0: можно читать следующий байт ресурсов), `0x06` CSN, `0x07` номер
  логического устройства.
- Регистры логического устройства: `0x30` Activate, `0x31` I/O range check,
  `0x60`/`0x61` базовый адрес I/O (старший/младший), `0x70` номер IRQ
  (`0` = нет), `0x71` тип IRQ.
- Конфликт `READ_DATA` на первой итерации (нет `55 AA` или неверная сумма)
  означает "перенести порт и повторить"; на последующих -- "карт больше нет".

## 4. Sprinter: ограничения и как они закрываются

| Требование | Как выполняется | Статус |
|---|---|---|
| Адреса `0x279`, `0xA79`, `READ_DATA` | окно ISA 16 КБ даёт A0..A13 (`isa.inc`): `0xC279`, `0xCA79`, `0xC000 + порт`; `PORT_ISA` остаётся `0` | по схеме да; дойдут ли A10/A11 до карты -- проверяет P4 |
| Шина без драйвера читается `FF` | подтяжки 4K3 на BD0..7 (R201..R208 по схеме Sprinter) | да |
| Такты ожидания не нужны | регистры PnP -- простые 8-битные | да, слабый IOCHRDY не задет |
| Паузы 1 мс / 250 мкс / 2 мс | только при **закрытом** окне ISA, как требует дисциплина окна | да |
| Настройка переживает работу пакета | проект нигде не выставляет `ISA_RST`; `ISA_OPEN` пишет `PORT_ISA = 0` | да; поведение BIOS при тёплом сбросе -- проверить в P4 |
| Несколько слотов | `ISA_OPEN` выбирает слот через `PAGE3` (`0xD4`/`0xD6`), обмен видит только выбранный слот | ключ `-s`, по одному слоту за запуск |
| Конфликт `READ_DATA` | на слоте одна карта; порт выбирается из короткого списка вне `0x300..0x31F` | да |

Правила из `CLAUDE.md` действуют полностью: DI -> `ISA_OPEN` -> обращения ->
`ISA_CLOSE` -> EI; никаких вызовов DSS/BIOS и пауз при открытом окне;
сначала собрать данные, потом печатать; каждое ожидание ограничено таймаутом
с диагностикой.

## 5. Проектные решения

### 5.1 Модуль `pnp_lib.asm` (MODULE PNP)

Точки входа, окно ISA открывает и закрывает сам модуль (паузы внутри
изоляции требуют закрытого окна):

```text
PNP.SEND_KEY        Wait for Key -> Sleep
PNP.RESET_CSNS      Config Control: reset CSN (все карты слота -> CSN 0)
PNP.ISOLATE         Wake[0], SET_RDPORT, 72 пары, проверка суммы;
                    Out: ID (9 байт), статус
PNP.ASSIGN_CSN      записать CSN изолированной карте
PNP.WAKE            Wake[CSN] -> Config
PNP.READ_RESOURCES  ограниченное по времени чтение ресурсных данных в буфер
PNP.SELECT_LDN      регистр 0x07
PNP.SET_IO          0x60/0x61, проверка чтением назад
PNP.SET_NO_IRQ      0x70 = 0
PNP.ACTIVATE        0x30 = 1, проверка чтением назад
PNP.WAIT_FOR_KEY    Config Control бит 1
```

Коды статуса: `PNP_OK`, `PNP_E_NOCARD`, `PNP_E_CHECKSUM`, `PNP_E_RDPORT`,
`PNP_E_TIMEOUT`, `PNP_E_VERIFY`. Модуль не печатает и не вызывает DSS,
поэтому пригоден и для сторонних программ SDK.

Память: буферы ID (9 байт на карту) и ресурсов (до 256 байт) -- `EQU` в
`memmap.inc` (отдельная область, без `DS n,0` в образе). Модуль подключается
только в `pnpcfg.asm`: сетевые утилиты и DLL не растут.

### 5.2 `PNPCFG.EXE`

```text
PNPCFG [-s N]                       список: найти карты, напечатать ID и
                                    ресурсы, вернуть их в Wait for Key
PNPCFG -c [-s N] [-n CSN] [-d LDN] [-b HEX]
                                    настроить: адрес (по умолчанию 300),
                                    IRQ нет, активировать, проверить
PNPCFG -r [-s N]                    сбросить CSN и вернуть в Wait for Key
PNPCFG /?                           справка
```

- Несколько ключей в командной строке -> большой вариант заголовка
  (`ORG 0x4100`, `CLAIM_RUNTIME_PAGE` первой инструкцией), как требует
  `CLAUDE.md`.
- Коды этапов: свободная буква `Q` (занятые: C E G L N P R T W X).

Ожидаемый вывод списка:

```text
PNPCFG v0.x.y
[Q0] Slot 1, READ_DATA=20B
[Q1] KEY sent
[Q2] CSN1 ID=CPX1501 SN=0012A4F0 CHK OK
[Q3] RES "Compex RL2000A PNP Ethernet" IO 200-3E0/20 IRQ 3 4 5 9 10 11
[Q9] cards back in WAIT FOR KEY
RESULT OK
```

Ожидаемый вывод настройки:

```text
[Q4] CSN1 LDN0 IO=300 IRQ=none
[Q5] ACTIVATE 30=01 60=03 61=00
[Q6] NE2000 at 300: CR=21 ok
RESULT OK
```

Проверка `[Q6]` использует существующую пробу присутствия драйвера.
Регистры страницы 0 `0x0A`/`0x0B` она не трогает: у клонов DP83905 это
скрытые CRA/CRB, чтение с последующей записью по тому же адресу
перепрограммирует карту.

Коды выхода: `0` успех; `1` командная строка; `2` на слоте нет PnP-карты
(ни одной пары `55 AA` ни на одном порту `READ_DATA`); `3` ошибка протокола
(сумма, таймаут ресурсов, проверка чтением назад, карта не ответила после
активации).

### 5.3 Встраивание в загрузку

Первая редакция -- строка в `AUTOEXEC`/`.BAT` до `NETCFG -i`:

```text
PNPCFG -c -b 300
NETCFG -i
```

Ключ в `NET.CFG` (например, `RTL_PNP=`) -- открытый вопрос: схема `NET.CFG`
закреплена, расширять её -- решение мейнтейнера (7.2). Дешёвое дополнение:
`NETCFG -i` и `IFUP`, не найдя карту ни по одному адресу, печатают подсказку
"card may be in PnP mode: run PNPCFG".

### 5.4 Харнесс

Модель PnP-карты поверх `rtl8019-model.js`: состояния Wait for Key / Sleep /
Isolation / Config, проверка ключа LFSR, выдача `55 AA` по битам серийного
ID, сумма, CSN, ресурсные данные с битом готовности, регистры `0x30`,
`0x60`/`0x61`, `0x70`. До активации NE2000-модель не отвечает, после
активации отвечает по записанному адресу. Декодирование `0xC279`, `0xCA79` и
`READ_DATA` добавляется в `harness.js` рядом с апертурой карты.

Сценарии: слот без карты (выход 2); PnP-карта в Wait for Key и список ID;
неверная сумма (выход 3); настройка на `0x300` и последующий `NICINFO`;
`NICINFO` без `PNPCFG` на PnP-карте (выход 2). Существующие инварианты
(дисциплина окна, DSS и пауза при открытом окне, IFF1) действуют.

### 5.5 MAME (необязательно)

В MAME нет эмуляции ISA PnP. В `kiselev_eth.cpp` (8-битная карта на
RTL8019AS) режим PnP числится в TODO ("93C46 EEPROM, jumperless and Plug and
Play configuration modes (SW1)"). Реализация этого режима дала бы приёмку в
MAME; это работа в репозитории MAME и отдельное решение.

  (двойное чтение, явный `-y`, проверка после записи).

## 7. Риски и открытые вопросы

### 7.1 Риски

- **A10/A11.** Если линии не доходят до слота, карта не увидит `0xA79`, и
  программная настройка PnP на Sprinter невозможна без доработки платы.
  Запасной путь -- один раз выключить PnP утилитой производителя на PC.
- **Тёплый сброс.** Если BIOS при сбросе выставляет RSTDRV, настройка
  теряется и `PNPCFG -c` нужен после каждого сброса, а не только после
  включения.
- **Нестандартные карты.** Часть карт (DM9008 в режиме jumperless)
  принимает только вендорный ключ; стандартный ключ их не разбудит. Это
  нормальный случай "PNPCFG не нужен", а не ошибка.
- **Порядок с драйвером.** `NETCFG -i` до `PNPCFG -c` карту не найдёт; это
  должно быть видно по подсказке (5.3), а не по молчаливому отказу.

### 7.2 Решения мейнтейнера (не приняты)

1. Ключ в `NET.CFG` или только строка в `.BAT`.
2. Буква кодов этапов (`Q` предложена).
3. Нужен ли P7 и в каком объёме.
4. Делать ли режим PnP в MAME `kiselev_eth` (5.5).

## 9. Критерии готовности

- `make test-host` зелёный со сценариями 5.4.
- На реальной PnP-карте: `PNPCFG` печатает ID с верной суммой; `PNPCFG -c`
  активирует карту на `0x300`; после этого `NICINFO`, `NICRAM` и `PING`
  проходят так же, как на карте без PnP.
- Без PnP-карты на слоте -- `[E...]`, выход 2, без зависаний.
- Ни одного ожидания без таймаута; диагностика понятна по одному снимку
  экрана.
