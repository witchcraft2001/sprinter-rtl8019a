# План стабилизации RTL8019AS на реальном Sprinter

Дата: 2026-07-12.

Документ определяет порядок исправления Sprinter ASM-реализации драйвера и
утилит RTL8019AS. Он основан на выводах `isa_issues_gpt_research.md`.

На первых этапах запрещено изменять:

- MAME и его модель `rtl8019as`/`dp8390`;
- прошивку Sprinter ACEX;
- электрическую схему Sprinter или сетевой карты.

Сначала должны быть устранены подтвержденные ошибки ASM-драйвера, управления
ISA-окном, packet RAM и диагностики. К MAME, ACEX или аппаратным переделкам
можно возвращаться только после выполнения всех этапов этого плана и
повторного тестирования на реальном Sprinter.

## 1. Цель

Добиться стабильной работы ISA8 RTL8019AS/NE2000-совместимой карты на реальном
Sprinter DSS:

- без чтений фиктивного `0xFF` из-за неправильного MMU/ISA lifetime;
- без повреждения состояния DSS и системной page 3;
- без длительного подавления системного IRQ;
- с корректной 8-битной картой packet RAM;
- с диагностируемыми timeout, RX overflow и remote-DMA errors;
- с последовательным прохождением всех утилит пакета.

Основной целевой чип остается RTL8019AS. Поддержка произвольных клонов NE2000
без ID `0x50/0x70` не должна расширять объем текущего исправления.

## 2. Основные подтвержденные проблемы

### 2.1. Неверный предел packet RAM

Драйвер использует:

```text
DCR.WTS=0
PSTART=0x46
PSTOP=0x80
```

Для RTL8019AS в byte-wide режиме `PSTOP` не должен превышать `0x60`.
Корректная карта памяти:

```text
TX:      0x4000..0x45FF
RX ring: 0x4600..0x5FFF
PSTOP:   0x60 (exclusive)
```

### 2.2. DSS/BIOS при открытом ISA-окне

Некоторые утилиты печатают или вызывают DSS после `RTL.INIT_BASE`, который
оставляет ISA-окно открытым. Любой DSS/BIOS-вызов внутри такого интервала
нарушает правила MMU page 3.

### 2.3. Длительные межбайтовые задержки DMA

Текущее незакоммиченное значение `RTL_DMA_SETTLE=32` добавляет задержку на
каждый байт remote-DMA, не удлиняя отдельный ISA-строб. При максимальном кадре
оно способно держать ISA-окно открытым и IRQ выключенными дольше периода
системного прерывания.

### 2.4. Недостоверный register snapshot

Текущий shadow-based snapshot не показывает фактически принятые чипом
DCR/RCR/TCR/IMR. RTL8019AS разрешает читать эти регистры с page 2.

### 2.5. Недостаточный `NICRAM`

Тест проверяет только нижнюю память от `0x4000` до приблизительно `0x45FF` и
не проверяет область будущего RX-кольца до `0x5FFF`.

## 3. Общие правила реализации

Каждая итерация, меняющая ASM-код, обязана завершаться:

```sh
make package image
```

Не допускается объявлять исправление готовым только после `make build`.
Перед передачей пользователю образа проверить наличие обновленных:

```text
distr/sprinter-rtl8019a.zip
distr/sprinter-rtl8019a.img
```

Правила ISA lifetime:

```text
DI
ISA_OPEN
только обращения к карте и копирование данных в обычную RAM
ISA_CLOSE
EI
только после этого DSS, BIOS, PRINT, SCANKEY, ENVIRON, file I/O и delay
```

Дополнительные правила:

- не включать `DCR.WTS=1` на ISA8;
- не добавлять скрытые бесконечные ожидания;
- не маскировать постоянную ошибку шины бесконечными повторами;
- сначала сохранять регистры в RAM, затем закрывать ISA и печатать;
- не смешивать несколько независимых гипотез в одной тестовой итерации;
- не изменять MAME или ACEX в рамках этого плана.

## 4. Итерация 1: исправить 8-битную карту packet RAM

### Изменения

В `src/include/rtl8019.inc`:

```asm
RTL_TPSR_INIT   EQU 0x40
RTL_PSTART_INIT EQU 0x46
RTL_PSTOP_INIT  EQU 0x60
RTL_BNRY_INIT   EQU 0x46
RTL_CURR_INIT   EQU 0x47
```

Обновить все связанные места:

- `sprinter_rtl8019_soft.md`;
- диагностические строки `NICLB` и других приложений;
- комментарии `src/include/memmap.inc` о размере RX-кольца;
- расчеты RX drain budget;
- проверки RX page и wrap;
- описание packet RAM в пользовательской/разработческой документации.

Не менять одновременно DMA delays и алгоритм overflow recovery: первая
сборка должна изолированно показать эффект нового `PSTOP`.

### Проверка

1. `make package image`.
2. На реальном Sprinter выполнить:
   - `NICINFO`;
   - текущий `NICRAM`;
   - `NICLB`.
3. Повторить каждый тест не менее 10 раз.
4. Сохранить полный вывод и значения BNRY/CURR.

### Критерий завершения

- карта стабильно определяется;
- нижняя packet RAM работает;
- loopback использует `PSTOP=0x60`;
- нет новых reset/RDC timeout.

## 5. Итерация 2: убрать межбайтовый DMA settle

### Изменения

- Установить `RTL_DMA_SETTLE=0`.
- Удалить или отключить вызовы `DMA_SETTLE` на каждый байт.
- Пока не вводить chunked DMA: сначала измерить поведение простого быстрого
  burst без искусственных пауз.
- Сохранить timeout RDC и clean abort после завершения.

### Проверка

1. `make package image`.
2. `NICRAM` -- не менее 20 последовательных прогонов.
3. `NICLB` -- не менее 20 прогонов.
4. Проверить отсутствие:
   - зависания клавиатуры;
   - экранных артефактов;
   - длительных пауз после DMA;
   - спонтанного выхода или выключения.

### Критерий завершения

Remote-DMA без settle стабильно проходит ранние тесты и не блокирует систему.

Если тест ухудшился, нельзя сразу возвращать большое значение 32/100. Нужно
зафиксировать адрес первого mismatch, CRDA и RDC, после чего проверить
минимальные значения 1, 2, 4 только отдельными A/B-сборками.

## 6. Итерация 3: исправить ISA lifetime в диагностических утилитах

### Приоритет файлов

1. `src/apps/nicinfo.asm`;
2. `src/apps/nicram.asm`;
3. `src/apps/niclb.asm`;
4. `src/apps/nictx.asm`;
5. `src/apps/nicrx.asm`.

### Изменения

- Закрывать ISA перед каждым `PRINT`, `PRINTLN`, `DSS_PCHARS`,
  `DSS_PUTCHAR`, `SCANKEY`, delay и exit.
- Повторно открывать ISA только непосредственно перед следующим доступом к
  карте.
- Error paths должны делать snapshot при открытом ISA, затем закрывать окно,
  затем печатать.
- Не использовать указатели в `0xC000..0xFFFF` после закрытия ISA.
- Проверить баланс каждого `ISA_OPEN`/`ISA_CLOSE` на всех переходах.

### Доработка `ISA_OPEN/ISA_CLOSE`

Отдельно оценить сохранение исходного состояния IFF:

- `ISA_CLOSE` не должен безусловно включать IRQ, если вызывающий код вошел с
  выключенными прерываниями;
- debug-вариант может хранить флаг `ISA_IS_OPEN` и обнаруживать повторный
  open или лишний close;
- изменение не должно добавлять BSS внутрь EXE: служебное состояние должно
  находиться в `memmap.inc`.

### Проверка

- Поочередно собрать и проверить пять ранних утилит.
- Не запускать сетевые протоколы до стабильного `NICRX`.
- Для каждой утилиты выполнить успешный путь и минимум один timeout/error
  path.

### Критерий завершения

Ни одна ранняя утилита не вызывает DSS/BIOS и не выполняет длинный delay при
открытом ISA-окне.

## 7. Итерация 4: восстановить фактическую диагностику NIC

### Изменения

`RTL.SNAPSHOT_REGS` должен захватывать:

- page 0: CR, ISR, BNRY, RSR, TSR, CRDA0/CRDA1;
- page 1: CURR;
- page 2: PSTART, PSTOP, TPSR, RCR, TCR, DCR, IMR;
- при необходимости page 3 RTL8019AS: CONFIG0..CONFIG4 и INTR.

Software shadows разрешается оставить только как дополнительный expected
набор. Вывод должен различать:

```text
DCR expected=48 actual=48
RCR expected=04 actual=04
TCR expected=00 actual=00
PSTART=46 PSTOP=60 BNRY=.. CURR=..
CRDA=....
```

При `0xFF`:

- повторить CR/ISR/ID не менее двух раз в одном коротком ISA-сеансе;
- не объявлять кольцо пустым только по одиночному `ISR=0xFF`;
- классифицировать ошибку как `BUS_FLOAT`, `BAD_RING`, `OVW` или
  `DMA_TIMEOUT`.

### Проверка

- Сравнить snapshot после reset, init, DMA write/read, loopback и timeout.
- Убедиться, что snapshot не меняет рабочую страницу/режим после возврата.
- Вся печать выполняется после `ISA_CLOSE`.

## 8. Итерация 5: расширить `NICRAM`

### Матрица тестов

```text
0x4000: 16, 64, 256, 1536
0x4600: 64, 256, 1536
0x5A00: 256
0x5F00: 256
0x6000: диагностический probe
0x7000: диагностический probe
```

Для `0x6000` и `0x7000` не задавать обязательное ожидаемое значение. Утилита
должна вывести результат как `FF`, `ALIAS`, `WRITABLE` или `OTHER`, но не
использовать эти адреса как рабочую RAM.

Дополнительно:

- pattern генерируется до открытия ISA;
- каждый DMA-тест выполняется в коротком ISA-сеансе;
- compare и print выполняются при закрытом ISA;
- при mismatch выводятся packet-RAM address, expected, actual, CRDA и
  фактические регистры;
- убрать оставшиеся `DS ...,0` runtime buffers из EXE и использовать
  `memmap.inc`/`APP_BSS_BASE`.

### Приемка

- минимум 50 полных прогонов на реальном Sprinter;
- все адреса `0x4000..0x5FFF` проходят;
- система остается отзывчивой;
- поведение `0x6000/0x7000` записано как диагностика, но не влияет на
  `RESULT OK` допустимой памяти.

## 9. Итерация 6: исправить RX ring и overflow recovery

### RX ring

- Все проверки должны использовать диапазон `[0x46,0x60)`.
- Wrap выполняется `0x5F -> 0x46`.
- До чтения тела валидировать:
  - RX status;
  - next page;
  - stored length;
  - вместимость destination buffer.
- Нельзя читать тело из packet RAM при недостоверном header.
- При ошибке заголовка ограничить число повторов и гарантированно продвинуть
  либо ресинхронизировать BNRY без бесконечного цикла.

### Overflow recovery

Разделить recovery на короткие фазы:

```text
open -> STOP + abort DMA -> close
delay при закрытом ISA
open -> RBCR=0, loopback, BNRY/CURR sync, clear OVW, resume -> close
```

Не очищать диагностически важные ISR-биты до их сохранения.
Учитывать, что `ISR.RST` может быть установлен при overflow.

### Проверка

- `NICLB` с несколькими последовательными кадрами;
- контролируемое заполнение кольца;
- wrap через `0x5F`;
- искусственный OVW;
- восстановление приема без перезапуска приложения.

## 10. Итерация 7: стабилизировать TX и базовый внешний RX

### Утилиты

1. `NICTX`;
2. `NICRX`;
3. `ARP`;
4. `PING`.

### Проверки

- TX frame имеет длину не менее 60 байт без FCS;
- PTX/TXE очищаются и проверяются корректно;
- RX работает с `RCR_AB`, без promiscuous по умолчанию;
- ARP request/reply корректно обрабатываются во время ожиданий;
- циклы ожидания закрывают ISA перед pacing delay и `SCANKEY`;
- timeout ограничен реальным бюджетом и не растягивается бесконечно под
  фоновым трафиком;
- RX drain budget соответствует кольцу из 26 страниц.

### Приемка

- `NICTX` виден внешним sniffer;
- `NICRX` принимает управляемые кадры;
- `ARP` стабильно разрешает адрес;
- `PING` выполняет не менее 1000 запросов на реальном LAN без зависания и
  повреждения экрана;
- отдельно повторить ping под управляемым broadcast traffic.

## 11. Итерация 8: унифицировать циклы ожидания приложений

Повторяющаяся логика ARP/RX/timeout сейчас находится во многих приложениях.
После стабильного `PING` вынести общий проверенный механизм либо привести все
копии к одному шаблону:

- ограниченный RX drain;
- decrement timeout и при пустом кольце, и под постоянным трафиком;
- обработка Esc/Ctrl+C;
- закрытие ISA перед delay/DSS;
- обработка DMA error без повторного чтения бесконечно одного BNRY;
- сохранение snapshot до печати;
- одинаковые exit codes.

Применить к:

- `IFUP`;
- `UDPTEST`;
- `NSLOOKUP`;
- `NTP`;
- `TFTP`;
- `WGET`;
- `FTP`.

1. `HELLO`;
2. `NICINFO`;
3. `NICRAM`;
4. `NICLB`;
5. `NICTX`;
6. `NICRX`;
7. `NETCFG`;
8. `IFUP`;

10. `PING`;

15. `WGET` 2/24/56 Кбайт;
16. `FTP` LIST/NLST/GET/PUT;

Для каждой утилиты проверить:

- success path;
- timeout;
- Esc/Ctrl+C;
- отсутствие карты;
- неверную конфигурацию;
- корректный `DSS_EXIT`;
- `RESULT OK`/`RESULT FAIL`;
- регистры и target data на timeout;
- отсутствие DSS-вызовов при открытом ISA.

## 13. Когда разрешено вернуться к MAME или ACEX

MAME и ACEX остаются вне текущего scope. Возвращение к ним разрешается только
если одновременно выполнены условия:

1. `PSTOP=0x60` применяется во всем ASM-коде.
2. `NICRAM` проходит 50 раз на `0x4000..0x5FFF`.
3. Нет DSS/BIOS-вызовов при открытом ISA.
4. `RTL_DMA_SETTLE=0` либо минимальное значение доказано A/B-тестом.
5. Actual page-2 snapshot работает.
6. RX wrap и overflow recovery проверены.
7. Ошибка все еще воспроизводится с сохраненными CRDA/BNRY/CURR/ISR.
8. Получены измерения `IORD`, `IOCHRDY`, `/WAIT` и data bus.

До выполнения этих условий нельзя объяснять оставшиеся ошибки только
коротким циклом ACEX или несовершенством MAME.

## 14. Итоговые критерии готовности Sprinter ASM

Реализация считается стабильной, когда:

- `NICINFO` всегда обнаруживает карту и MAC;
- `NICRAM` проходит 50 последовательных полных циклов;
- `NICLB` стабильно проверяет PTX и receive-side loopback: RX payload в
  MAME либо ISR/RSR/FIFO на физическом RTL8019AS; внешний RX payload
  проверяет `NICRX`;
- RX корректно проходит wrap и восстанавливается после OVW;
- `PING` выполняет 1000 запросов под контролируемой нагрузкой;
- `UDPTEST`, `NSLOOKUP` и `NTP` проходят сериями;
- `TFTP`, `WGET` и `FTP` передают файлы с совпадающей длиной и содержимым;
- экран, клавиатура, DSS и питание остаются стабильными;
- отсутствуют скрытые infinite waits;
- каждая ошибка дает достаточный register/target dump;
- финальный `make package image` успешно создает ZIP и IMG.

## 15. Ближайшая реализационная очередь

Первый рабочий цикл должен включать только:

1. `PSTOP=0x60` и связанные константы/документацию;
2. сборку `make package image`;
3. проверку `NICINFO`, `NICRAM`, `NICLB` на реальном Sprinter;
4. фиксацию вывода до следующих изменений.

После подтверждения переходить к `RTL_DMA_SETTLE=0`, затем к аудиту ISA
lifetime. Такой порядок позволяет установить вклад каждого исправления и не
замаскировать исходную причину большой одновременной переработкой.
